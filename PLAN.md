# Plan — fully working Catan Universe custom server

Definition of done: with the mod set to `Custom`, a player can register/login, reach the main menu (free-tier or mirrored-purchase entitlements),
edit profile, play vs AI, play online (quick match + custom lobby with friends) to the end incl. reconnect,
chat, see results/leaderboards, use friends/guilds. No dependency on official servers (CDN asset bundles excepted).

## Architecture
```
Game (BepInEx mod: startup server picker → NakamaConfig, traffic log)
  └─ Nakama SDK 3.17 ── HTTP/WS ──> Nakama 3.41 (podman) + Postgres
                                      └─ server/ TS runtime module = reimplemented GameSparks-style backend
```
- One dispatcher RPC function registered for every known id; routes on payload `eventKey` / `@class`.
  Unknown ids → logged + generic success, so the client never stalls (gap list grows from logs).
- Nakama built-ins wherever they fit: users/auth, friends, groups (guilds), notifications (GS pushes),
  storage (profile, game sessions, state blobs), leaderboards, matchmaker, chat.
- Content (shop, seasons, tournaments, news, terms) = static JSON in `server/data/` (catalogs: ids only, no USM text; almanac optional, host-generated by `tools/gen-almanac.py`). Entitlements derived per read (`entitlements.ts`): free tier by default, own official purchases on `owned` servers; nothing is sold.

## Testing strategy (cheap first)
1. `server/test/` bot scripts — fast, no game; every handler gets a scripted call.
2. Fixture diff vs captured PROD responses (shape-level: keys/types).
3. Headless game run + `BepInEx/traffic.jsonl` grep for errors/unknown ids — only for integration checkpoints.

## Agent workflow (token efficiency)
- Every agent: read `CLAUDE.md` + only the spec section it needs; owns explicit files; no commits; report ≤15 lines.
- Sonnet for spec extraction and implementing well-specified handlers; Opus for architecture, debugging, multiplayer core.
- Never read full decomp files; grep + `sed -n` ranges.
- Specs are the contract: implementation agents cite spec ids, and fix the spec when the game disagrees.

## Risks / open questions
- Game logic is peer-replicated lockstep (all clients run rules; server stores/relays opaque Thrift action blobs, elects hostIdx for AI seats, owns kick/AFK/presence, computes results). Unknowns: ACTION_ID validation (err 111), timer lengths, ELO formula → pick sane values.
- Responses whose shape can't be inferred from decomp → need Phase 2 captures.
- Steam auth / entitlements checks client-side (expansions, DLC) — see economy-ranking.md.
- Asset bundles from `cdn.catancdn.de` — keep official CDN; mirroring is a later preservation task.
